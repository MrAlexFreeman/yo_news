# Ё-новости — контекст проекта

Файл для передачи контекста сторонним AI-моделям и разработчикам. Содержит только
проверенные факты из кодовой базы, `prisma/schema.prisma` и конфигурации сервера.

Обновлён: 2026-10-10. Если что-то здесь расходится с кодом — **код прав**. Этот файл
описывает код, а не наоборот.

## 1. О проекте и бизнес-логике

| | |
|---|---|
| Название | «Ё-новости» |
| Домен | `eartnews.ru` |
| Специфика | Городское / региональное новостное издание (Екатеринбург и Средний Урал) |
| Слоган | «События, о которых говорят» |
| Позиционирование | «Новости Екатеринбурга и мира» |
| Реплика | «Сетевое издание Ё-новости» |

Материалы — перепечатки проволочных агентств (e1.ru, ura.ru) плюс собственные
редакторские тексты. Каналы распространения — сайт, VK, Telegram, MAX, Дзен.
Монетизация — реклама.

### 1.1. Роли

Права в системе **не разделены**: один аккаунт (`ADMIN_USER` / `ADMIN_PASSWORD`,
Basic Auth на весь `/admin`) на всех. В коде нет ролей «администратор» и
«редактор» — есть «вошёл в админку» и «не вошёл». Подробнее — раздел 3.6.

- **Редактор** — пишет материалы, ставит тэги, рубрики, обложки, решает, куда уйдёт
  материал (Дзен, ВК, Telegram, MAX), публикует.
- **Администратор** — то же самое, плюс `/admin/settings` (ключи API, токены
  мессенджеров) и `/admin/entities` (карточки объектов).

Требование, зафиксированное в коде: **простота важнее функциональности**. Редактор —
журналист, а не администратор CMS. Незнакомое поведение обязано объясняться текстом
рядом с полем, а не молча игнорироваться.

### 1.2. Публичная часть

- Главная: лид-материал, «В центре внимания» (полоса главных тем), река новостей,
  ленты по рубрикам, спецтемы, блок мнений.
- Страница материала: обложка с подписью и лицензией, галерея, видео, тело с
  врезкой «Читайте также», блок «Продолжить чтение», сайдбар «Сейчас читают»,
  карточки объектов во всплывающей подсказке.
- Разделы: рубрики (с пагинацией), тэги, поиск, форум, страницы «О редакции».
- Живые элементы: строка даты/времени, бегущая строка тем.

### 1.3. Рубрики

Список один на весь проект (`src/lib/categories.ts`) — его читают шапка, подвал,
выпадающий список админки и сид. Порядок задан явно (не по алфавиту):

`Расследования` · `Здоровье и стиль` · `Дом и сад` · `Кино и сцена` ·
`Происшествия` · `Общество` · `Экономика`

Рубрики, отменённые реформой 2026 года (`politics`, `tech`, `science`, …),
переназначены в `society`; материалы сохраняют свои URL, старые адреса рубрик
редиректятся.

### 1.4. Конвейер публикации

```
«Предложка» (лента e1.ru / ura.ru)
        ↓
    Черновик (редактор)
        ↓
   «Применить» / «Опубликовать»
        ↓
  ┌─ Дзен (isDzen) ──────────────► /api/feed/dzen.xml (RSS)
  ├─ ВК (isVk) ───────────────────► стена сообщества
  ├─ Telegram (isTelegram) ───────► канал
  ├─ MAX (isMax) ─────────────────► канал
  └─ Сайт ───────────────────────► /news/[slug]
```

### 2.2. База данных и ORM

- **Провайдер: SQLite** (`provider = "sqlite"` в `prisma/schema.prisma`), файл
  `prisma/dev.db`. **PostgreSQL не используется** — ни локально, ни на сервере.
- ORM: **Prisma 7.10.0** с драйвером `@prisma/adapter-better-sqlite3`.
- Клиент генерируется в `src/generated/prisma` (каталог в `.gitignore`).
- Миграции: 17 штук в `prisma/migrations/`, по одной на изменение схемы.

**Критичное правило SQLite:** новые колонки — **только в конец модели**. Вставка
колонки в середину заставляет Prisma пересоздать всю таблицу `Article`, что теряет
данные. Поэтому в схеме порядок значим: новые колонки (`vkPostId`,
`autoRelatedArticle`, `stock*`) стоят в конце.

Основные модели:

| Модель | Назначение | Ключевые поля |
|---|---|---|
| `Article` | Материал | `id`, `title`, `slug` (@unique), `lead`, `contentHtml`, `coverImage`, `status` (`draft` \| `published`), `categoryId`, `views`, `publishedAt`, `deletedAt` |
| `AppSetting` | Настройки и ключи | `key` (@id), `value`, `updatedAt` |
| `Tag` | Тэги | `id`, `name`, `nameKey` (@unique), `slug` (@unique) |
| `Category` | Рубрики | `id`, `name`, `slug` |
| `NewsFeedItem` | «Предложка» | `id`, `source` (`E1`/`URA`), `externalId` (@unique), `status` (`NEW`/`DRAFTED`/`IGNORED`) |
| `EntityCard` | Карточки объектов | `id`, `slug` (@unique), `title`, `category`, `summary`, `images` (JSON) |
| `ForumCategory` / `ForumTopic` / `ForumPost` | Форум | таблицы в snake_case через `@map("forum_*")` |
| `ArticleTag` | Связь материалов и тэгов | `articleId`, `tagId`, составной `@id` |

Флаги распространения на `Article`: `isDzen`, `isVk`, `isTelegram`, `isMax` — все
`@default(true)`; `isExclusive`, `is18plus` — `@default(false)`.

Редакторские решения: `dzenExperiment` (только при первой публикации), `dzenDirect`,
`autoRelatedArticle` (`@default(true)`), `searchText` (lowercased «title lead» для
поиска), `noIndex`, `seoTitle` / `seoDescription` / `seoCanonicalUrl`, `vkPostId`.

### 2.4. Менеджер процессов и деплой

Приложение под PM2: `uartnews`, команда `next start`, порт 3000.

**Деплой — строго через `bash deploy.sh` на VPS.** Скрипт выполняет по порядку:

```
git fetch + reset --hard origin/main
npm ci            (postinstall → prisma generate)
prisma generate   (отдельно — это ключевой шаг)
prisma migrate deploy
npm run build
pm2 reload uartnews
```

Почему порядок именно такой: `src/generated/prisma` не в git, и после `git reset`
код может ссылаться на модели, которых в сгенерированном клиенте нет. Симптом —
`error TS2339: Property 'forumTopic' does not exist on type 'PrismaClient'`, который
выглядит как сломанная схема, а не как отсутствующий сгенерированный файл.

Переменные окружения скрипта: `PM2_APP` (имя процесса, по умолчанию `uartnews`),
`PM2_SKIP_PULL=1` / `--skip-pull`, `SKIP_CA_SETUP=1`.

**Запрещено: использовать `tools.browser` (headless-браузер) при проверке и деплое.**
Вызовы браузера в этом окружении зависают. Проверка ведётся через `curl`, чтение
HTML, запросы к API, логи PM2 и прямые запросы к SQLite.

### 2.5. PWA / TWA

- **Android-приложение — TWA поверх этого сайта.** Манифест отдаётся из
  `public/manifest.json`, а **не** из маршрута `app/manifest.ts`. Причина измерена:
  Next отвечает на `/manifest.webmanifest`, экспорт `path` там не работает, а при
  существующем маршруте Next сам печатает `<link rel="manifest">` и переопределяет
  это поле. `.json`-файл — единственный способ попасть на URL, для которого собрана
  TWA (`app/manifest.ts` был удалён после замера).
- Манифест: имя «Ё-Новости», `display: standalone`, `theme_color: #ffffff`, иконки
  192/512 в вариантах `any` и `maskable`.
- Иконки генерируются `scripts/generate-pwa-icons.mjs` через sharp и коммитятся:
  `icon-192.png`, `icon-512.png`, `apple-touch-icon.png`.
- Root layout (`src/app/layout.tsx`) добавляет `appleWebApp` (`capable`,
  `statusBarStyle`, `title`), иконки и alternate-ссылку на RSS.
- Отдельного APK в репозитории нет; стратегия — развивать PWA, не добавляя нативную
  обёртку.

## 3. Ключевые подсистемы и их архитектура

### 3.1. Интерфейс админки

Реплика классической редакционной системы (образец — CMS «Московского Комсомольца»,
mk.ru), привычная журналисту.

**Форма материала — четыре вкладки** (`article-form.tsx`, `TABS`):

1. **Материал** — заголовок, подзаголовок, анонс (лид), визуальный редактор.
2. **Медиа** — обложка, галерея, видео, подпись и лицензия фото.
3. **Тэги** — редактор тэгов с автодополнением.
4. **SEO** — `seoTitle`, `seoDescription`, канонический адрес, `noIndex`.

**Заголовок со счётчиком знаков** (`title-field.tsx`, константы в `types.ts`).
Изначально замысел был «больше 70 символов — красным и не давать сохранить». Это
изменилось **намеренно**, и цифры теперь такие:

| Лимит | Значение | Смысл |
|---|---|---|
| `TITLE_SOFT_LIMIT` | 250 | Предупреждение, не блокировка. Длинные заголовки расследований нормальны; редакторы постоянно упирались в прежние 70 |
| `DZEN_TITLE_LIMIT` | 200 | Янтарная полоса: дальше Дзен молча обрежет заголовок в своей ленте |
| `TITLE_MAX_LENGTH` | 300 | Жёсткий потолок, проверяется и на клиенте, и на сервере |

Мягкий лимит важнее жёсткого: редактор должен получать сигнал, а не отказ.

**Правый сайдбар («Свойства»)**: блок «Распространение» (чекбоксы «В Дзен-блог»,
«Репост в ВК», «Репост в Telegram», «Репост в MAX»), блок врезки «Читайте также»
(`autoRelatedArticle`), блок «Синдикация и эксперимент Дзен», рубрика, статус,
дата публикации, эксклюзив, 18+, тайтл/картинка для Дзена.

**Липкий подвал (Sticky Bar)**: «Сохранить» (зелёная), «Применить» (синяя),
«Отменить» (серая, возврат к последнему сохранённому состоянию) и «**В корзину**» —
не «Удалить»: строку помечают `deletedAt`, материал можно вернуть из корзины.

**Редактор** — Tiptap, оформленный под классическую панель CKEditor 4 («серая
полоса, сгруппированные кнопки»). Схема собрана в `editor-extensions.ts` — это не
стиль, а необходимость: Tiptap удаляет из тела при сохранении всё, что не знает его
схема. Поэтому любой новый блок (видео, таблица, карточка объекта, «Читайте также») —
это **решение о сохранении данных**, а не просто фича. Особенности:

- `Link` настроен с `inclusive: false`, иначе буква, набранная сразу после ссылки,
  прилипает к ней.
- Изображение — блок (`inline: false`), base64 запрещён (`allowBase64: false`).
- Атомарная нода обязана что-то сериализовать: пустой `<figure class="read-also">`
  без ссылки сохраняется как пустая фигура, а не исчезает.

### 3.2. Работа с медиа и файлами

**Расположение.** `UPLOAD_DIR` задаётся переменной окружения (на VPS
`/var/www/uartnews/uploads`), по умолчанию `<cwd>/uploads`. Файлы **не** лежат в
`public/`: Next снапшотит `public/` при старте, и файл, записанный в рантайме, по
такому пути отдаёт 404. Отдача идёт через маршрут `/uploads/[...path]`
(`src/app/uploads/[...path]/route.ts`), читающий с диска на каждый запрос.

**Форматы на входе:** `.jpg`, `.jpeg`, `.png`, `.webp` (`contentTypeFor`).

**Безопасность путей.** `resolveUploadPath` (`src/lib/upload-dir.ts`) — единственный
перевод `/uploads/...` в абсолютный путь. Он декодирует процентное кодирование,
отклоняет NUL-байты, резолвит путь и проверяет, что результат строго внутри
`UPLOAD_DIR`; при любом выходе за пределы (включая `..`) возвращает `null`.

**SSRF-защита.** Эндпоинты, скачивающие изображения, не принимают произвольный URL.
`src/lib/unsplash.ts` содержит allowlist хостов (`isFetchableUnsplashImage`), а
`stock-download` принимает **только `photoId`** (с проверкой
`/^[A-Za-z0-9_-]{4,64}$/`) и перечитывает адрес картинки из ответа Unsplash —
маршрут физически не может быть использован для SSRF. Обложка читается через
`readCoverImage` (`src/lib/cover-image.ts`): либо файл из `UPLOAD_DIR`, либо загрузка
по `https://` с таймаутом.

**Галерея** хранится как JSON в `Article.media` — не отдельной таблицей: у картинки
нет полей, по которым стоит искать, она читается только упорядоченным списком.

### 3.3. Апскейл обложек

Нужен потому, что обложки часто приходят маленькими из лент и из Unsplash, а сайт
показывает их во всю ширину десктопа.

**Локальный Real-ESRGAN отклонён и не должен возвращаться.** Причины, зафиксированные
в коде:

- на сервере 1 vCPU и **нет GPU** (только виртуальный Cirrus Logic);
- реальная обложка 6.8 МБ на одном vCPU обрабатывалась **более 20 минут** — сайт в
  это время не отвечал;
- попытка была откачена целиком, все артефакты удалены из репозитория и с сервера.

**Приоритет провайдеров** (`resolveUpscaleProvider`, `src/lib/image-upscale.ts`):

1. **fal.ai** — основной боевой провайдер. Модель `fal-ai/esrgan`, очередь
   `https://queue.fal.run`. Ключ `FAL_API_KEY` в `/admin/settings`. fal забирает
   картинку с открытого интернета, поэтому локальный файл предварительно упаковывается
   в base64 (`toFalImageInput`).
2. **Hugging Face** — запасной вариант. Модель `caidas/swin2SR-classical-sr-x2-64`
   (Apache-2.0). Ключ `HUGGINGFACE_API_KEY`. Названная в исходном техзадании
   `akhaliq/Real-ESRGAN` на хабе отдаёт 401 и **не существует** — заменена рабочей
   альтернативой. HF отвечает 503 при холодном старте, поэтому в `src/lib/hf-upscale.ts`
   есть повторные попытки и проверка «магических байтов»: 200-ответ, который не
   картинка, не считается успехом.

Если оба ключа не заданы, `resolveUpscaleProvider` возвращает `null`, и редактор
видит внятное сообщение, а не ошибку. Сообщение зависит от стадии: отсутствующий ключ
чинится в настройках, таймаут — повтором, нечитаемый файл — другой загрузкой.

### 3.4. Врезка «Читайте также»

Два режима, переключаемые флагом `autoRelatedArticle` (`@default(true)`).

**Автоматический режим (по умолчанию).** Сайт сам выбирает материал из той же рубрики
по стабильному хешу `article.id` и вставляет врезку после 2-го или 3-го абзаца
(`src/lib/content-loop.ts`, `placementFor` / `splitForLoop`). Хеш нужен, чтобы ISR-кэш
и следующая регенерация давали одно и то же положение — иначе врезка «прыгала» бы
между запросами. Тело делится на `before` / `after`, врезка рендерится между ними на
сервере.

**Ручной режим (флаг снят).** Автоматическая вставка отключается. В тулбаре редактора
появляется кнопка «📰 Вставить "Читайте также"» и попап с живым поиском по
опубликованным материалам. В документ вставляется нода `readAlsoBlock`.

**Как хранится ручная врезка — важно.** В теле статьи лежит только маркер:

```html
<figure class="read-also"><a href="/news/slug">Заголовок</a></figure>
```

Без обложки, времени чтения и рубрики. Страница находит такие маркеры
(`splitAroundReadAlso`, `src/lib/read-also.ts`), подтягивает живые строки и рендерит
тот же компонент `ReadAlsoBlock`, что и автоматическую врезку. Так один рендерер
вместо двух, и обложка не «застывает» на момент вставки. Своя врезка редактора всегда
побеждает автоматическую.

Если у привязанного материала нет обложки, рендерится аккуратный текстовый вид без
«битой картинки». Миниатюра — 80px на телефоне и 120px от `sm`, `object-cover` на
квадратной рамке, с `width`/`height`, чтобы абзац не прыгал при загрузке.

**Открытие вкладок.** Хук сантайзера проставляет `target="_blank"` только внешним
ссылкам. Внутренние (относительный путь, `#фрагмент`, свой домен) идут без `target`.
Протокол-относительные `//host/…` проверяются **до** относительных — иначе ссылка на
чужой хост теряла бы защиту (`isInternalHref`, `src/lib/dompurify.ts`).

### 3.5. Автопостинг и интеграции

**ВК (ВКонтакте).** `src/lib/vk-publisher.ts` + `vk-claim.ts` + `vk-dedupe.ts`.

- Публикация — трёхшаговый пайплайн VK: `photos.getWallUploadServer` → загрузка
  байтов на `upload_url` (multipart) → `photos.saveWallPhoto` → `wall.post`.
- **Положительный `group_id`** в `getWallUploadServer` и `saveWallPhoto`;
  отрицательный `owner_id` нужен только для `wall.post`. Это разные требования одного
  API, и перепутать их легко: `getWallUploadServer` принимает оба и молчит.
- `saveWallPhoto` возвращает массив объектов фото, из которых собирается
  `photo{owner_id}_{id}`; ответ приходит **без обёртки `response`**.
- Сервер загрузки VK отвечает 504 примерно в четверти попыток (замерено на пяти
  обложках, независимо от размера файла), поэтому загрузка повторяется до 5 раз с
  растущей паузой.
- **Ссылка во вложениях `attachments` не принимается** VK (ошибка 100 на всех версиях
  API от 5.92 до 5.199) — ссылка остаётся в тексте поста.
- Дедупликация: колонка `vkPostId` + атомарный claim в строке (`UPDATE … WHERE
  vk_post_id IS NULL`). Двойной submit и повторное сохранение опубликованного
  материала дублей не создают.
- Токен читается из настроек (БД), а не только из `.env`, чтобы ключ менялся без
  перезапуска.

**Дзен / RSS.** `src/lib/dzen-feed-html.ts` + `dzen-publication.ts`.

- Лента — `/api/feed/dzen.xml`, даты в RFC-822, до 50 последних материалов.
- «Эксперимент с Дзен» включается **только в момент первой публикации** — правило
  проверяется на сервере (`dzen-experiment.ts`), а не только отключённым чекбоксом.
- Метод публикации выбирается по паре флагов и пишется в `<category>`:
  `native-draft` (на модерацию), `format-article` (сразу статьёй), `format-post`
  (короткий пост).
- Очистка ленты — политика `dzen` в DOMPurify: `iframe` удаляются, ссылки
  абсолютизируются к домену сайта (Дзен скачивает их сам).

**Telegram / MAX.** `telegram-publisher.ts`, `max-publisher.ts`. Флаги `isTelegram` /
`isMax`, по умолчанию `true`. Токены и id каналов — в `/admin/settings`; список
разрешённых ключей в `settings-keys.ts`.

**Стоки (Unsplash).** `unsplash.ts` + `stock-credit.ts` + `stock-query.ts`.

- Ключ `UNSPLASH_ACCESS_KEY`. Бесплатный план — **50 запросов в час**, общие для
  поиска и скачивания. Поэтому поиск по кнопке, а не по каждой букве; есть
  60-секундный кэш; редактору показывается остаток.
- Запрос переводится на английский через DeepSeek (`stock-query.ts`): Unsplash
  индексирует английские подписи, русский запрос почти не находит. Названия городов и
  организаций из запроса исключаются — обложка с названием города обнуляет выдачу.
- Скачивание: `download_location` обязателен по правилам API, изображение
  перекодируется в WebP шириной 1080 через sharp. Атрибуция Unsplash хранится в
  четырёх колонках `stock*` и ведёт на профиль автора и страницу снимка (в
  `photoSource` ссылку положить нельзя — поле рендерится текстовым узлом и уходит в
  RSS текстом).

**Карточки объектов.** `entity-card.ts` + `/api/entities/[slug]` + `/admin/entities`.
Ссылка внутри материала — обычный путь `/entities/<slug>`, а не `data-*` и не
кастомная схема: `ALLOW_DATA_ATTR` выключен, а относительный путь переживает
отключённый JS и потому имеет собственную страницу.

### 3.6. Доступ и настройки

**Авторизация** — Basic Auth на весь `/admin` через `src/proxy.ts` (бывший
`middleware.ts`). Сравнение пароля — `timingSafeEqual`, realm латинский (кириллица в
HTTP-заголовке роняет guard в 500). Это «первый замок на двери», а не система
идентификации: ни аккаунтов, ни сессий, ни аудита.

**Настройки** — `AppSetting` в БД плюс `.env`, приоритет у БД. Список ключей, которые
можно читать и писать через API, ограничен `ALLOWED_KEYS` (`settings-keys.ts`):
`DEEPSEEK_API_KEY`, `DEEPINFRA_API_KEY`, `VK_ACCESS_TOKEN`, `TELEGRAM_BOT_TOKEN`,
`TELEGRAM_CHANNEL_ID`, `TELEGRAM_ENABLED`, `TELEGRAM_API_ROOT`, `MAX_BOT_TOKEN`,
`MAX_CHAT_ID`, `MAX_ENABLED`, `LIVE_STREAM_ENABLED`, `LIVE_STREAM_URL`,
`LIVE_STREAM_TITLE`, `FAL_API_KEY`, `HUGGINGFACE_API_KEY`, `UNSPLASH_ACCESS_KEY`.

Белый список обязателен: без него эндпоинт настроек отдал бы любой секрет процесса,
включая `ADMIN_PASSWORD`.

## 4. Жёсткие правила и ограничения

Не рекомендации. Нарушение ломает прод или данные.

### 4.1. Вычисления

- **Никаких тяжёлых нейросетевых вычислений на CPU сервера.** Ни локального апскейла,
  ни транскрибации аудио, ни видеокодирования, ни крупного OCR. 1 vCPU, ~370 МБ
  доступной RAM, GPU нет.
- Нейросети — только через внешние API (fal.ai, Hugging Face, DeepSeek, DeepInfra).
  Если задача требует локальной модели — она не для этого сервера.
- Долгие операции обязаны иметь таймаут и понятное сообщение об ошибке.

### 4.2. Проверки

- **Перед каждым коммитом — `npm run check`.** Это 20 наборов: типы, линт,
  security-набор (700+ проверок), витрина, лента, мультипарт, форум, Дзен, ВК,
  редактор, медиа, «Читайте также» и другие.
- Наборы, которым нужен dev-сервер на `localhost:3000`, падают, если он не запущен.
  Запускать с `NODE_OPTIONS=--max-old-space-size=3072` — иначе `npm run dev` падает по
  памяти (`Zone Allocation failed`).
- **Не останавливайте dev-сервер до конца `npm run check`.**
- После правки `prisma/schema.prisma` — обязательно `npx prisma generate`, иначе
  типы устаревают молча.
- Правило линтера `react-hooks/set-state-in-effect`: состояние закрытого диалога
  сбрасывается через смену `key` или начальное значение, а не `setState` в эффекте.
- Проверка должна утверждать **измеренное поведение**, а не ожидаемое. Стаб, который
  кодирует предположение вместо реальности, зелёный и бесполезный; такое уже
  случалось (см. раздел 5).

### 4.3. Совместимость и данные

- **100% обратная совместимость с существующей базой и статьями.** Никаких
  пересозданий таблиц, переименований колонок, миграций, ломающих сохранённые
  материалы.
- Новая колонка в `Article` — **только в конец модели** (ограничение SQLite).
- Новое поле получает значение по умолчанию, совпадающее с прежним поведением, — как
  у соседних флагов распространения.
- Мягкое удаление: `deletedAt`. Публичные пути фильтруют `deletedAt: null`, корзина
  возвращает материалы.
- **Не перезаписывать чужие файлы.** Задача может подразумевать «создать файл», а
  файл с таким именем уже есть в репозитории — сначала посмотреть, что там.

### 4.4. Инструменты и процесс

- **Деплой — только `bash deploy.sh` на VPS. Без `tools.browser`.** Headless-браузер
  здесь зависает.
- Проверка боевого поведения — `curl`, чтение HTML, запросы к API, логи PM2, прямые
  запросы к SQLite. Скриншоты не используются.
- Файлы пользователя в рабочей папке, не относящиеся к проекту (изображения, ярлыки,
  каталоги), — **не трогать** и не коммитить.
- Временные пробники удалять из репозитория и с сервера после использования.
- Изменения, затронувшие опубликованный контент, — сообщать явно, а не «прибирать»
  молча.

### 4.5. Работа с сервером напрямую

```bash
# Пароль лежит в .env в кавычках — это важно при чтении
grep '^ADMIN_PASSWORD=' .env | cut -d= -f2- | sed -e 's/^"//' -e 's/"$//'

# Отдельного sqlite3 на сервере нет — используется встроенный node:sqlite
node -e 'const {DatabaseSync}=require("node:sqlite");
         const db=new DatabaseSync("prisma/dev.db");
         console.log(db.prepare("SELECT count(*) c FROM Article").get());'
```

Файлы `.ps1` читаются PowerShell 5.1 как Windows-1251 и портят кириллицу — для проб
использовать bash-скрипты или `.mts` через `npx tsx`.

Локальная машина **не может** обращаться к `api.unsplash.com` (connection reset) —
Unsplash проверяется с VPS. До `api.vk.com` доступ локально есть.

## 5. Частые ловушки

| Ловушка | Почему так |
|---|---|
| `git reset --hard` стирает сгенерированный Prisma-клиент | `src/generated` в `.gitignore` |
| `middleware.ts` не работает | Next.js 16: файл называется `proxy.ts` |
| Поиск по заголовкам не находит кириллицу | SQLite `LIKE` и `LOWER()` — только ASCII; для этого есть `searchText` |
| Врезка «Читайте также» прыгает между запросами | Положение обязано быть хешем `article.id`, не случайным |
| Посты в ВК дублируются | Публикация — только при **переходе** в `published`, не при каждом сохранении |
| Обложка не прикрепляется к посту ВК | Отрицательный `group_id` в `saveWallPhoto`; ответ без обёртки `response`; массив вместо строки |
| `npm run dev` падает по памяти | Нужен `NODE_OPTIONS=--max-old-space-size=3072` |
| Ссылка на чужой сайт теряет `target="_blank"` | `//host/…` проходит проверку схемы — проверять до относительных |
| Ответ Unsplash на русский запрос пустой | Нужен перевод на английский и исключение названий городов |
| Тест зелёный, прод сломан | Стаб повторял предположение, а не ответ сервиса |
| `/manifest.json` отдаёт 404 | Существует маршрут `app/manifest.ts` — он переопределяет поле `manifest` |
